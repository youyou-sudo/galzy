# 说明

任务完成后，调用 `question` 工具向用户提供下一步选项，避免用户在没有引导的情况下不知道该做什么。

## Question 工具调用规则

### 必填字段（三个缺一不可）

每个问题对象必须同时包含：
- `question` — 完整的问题句子（**最容易被遗漏**，`header` 不是它的替代品）。  
  **当刚完成子代理调度任务时：`question` 字段必须综合总结所有相关子代理的汇报结果和当前任务状态，形成给用户看的整合性问题句子**，而不是泛泛的"下一步？"。例如：实现子代理报告 DONE、reviewer 子代理通过后，`question` 应写成"实现已完成且通过审查，所有变更已就绪，是否提交到版本库？"而不是"功能完成，下一步？"
- `header` — 极短标签，不超过 30 字符（不能把长总结塞进 `header`）
- `options` — 选项数组

缺少任何一个字段都会导致工具调用报错：`Invalid input: expected string, received undefined`

### 可选的上下文选项

根据刚完成的任务，额外提供 1–4 个具体的下一步选项，例如（不要照搬，根基上下文实际情况）：

- 运行测试
- 提交代码
- 创建 PR
- 查看日志
- 部署到生产

### 选项总数

最少 1 个（只有 🌟 推荐选项），最多 6 个。选项要具体。

### 推荐选项规范

每次调用 `question` 工具，`options` 中**必须始终有且仅有一个 `🌟` 选项**，没有例外。

**🌟 选项必须是让 Agent 继续干活的行动。** 例如：
- 查看有什么待办事项或未完成任务
- 找代码里可以优化的地方
- 发起一轮代码审查或重构
- 清理技术债或改善代码质量
- 继续推进上下文中未完成的功能

**禁止的 🌟 选项类型：**
- 被动等待（"等待用户指令"、"告诉我下一步"）
- 什么都不做（"完成"、"退出"）

**格式规则：**
1. **把该选项放在数组的第一位**（最显眼位置）
2. **在 `label` 末尾追加 `🌟`**，例如 `"扫描待办事项 🌟"`
3. **`description` 中说明要做什么以及推荐理由**

只标记**一个**推荐选项；不能把所有选项都标记为推荐。

## 示例

### 任务完成，有推荐选项

```
question({
  questions: [{
    question: "实现子代理已完成代码变更并通过自审，所有修改文件已就绪，下一步是否运行测试验证？",
    header: "下一步",
    options: [
      { label: "运行测试 🌟", description: "推荐：刚完成代码修改，先跑测试可以立刻发现回归。" },
      { label: "提交代码", description: "创建 git commit" }
    ]
  }]
})
```

### 无任务可做（纯闲聊或无后续动作）

```
question({
  questions: [{
    question: "还有什么需要我帮忙的？",
    header: "下一步",
    options: [
      { label: "扫描待办事项 🌟", description: "推荐：检查项目中是否有未完成的任务、技术债或可优化的地方，保持 Agent 持续生产性。" }
    ]
  }]
})
```
